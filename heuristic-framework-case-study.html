Overview

A computer vision platform analyzing human movement needed metrics that could actually measure what a coach's subjective expertise was evaluating, not just approximate it. The first version did neither well: a single set of metrics translated from one professional coach, an imperfect way to measure the aspects of a user's motion that actually mattered.

This is the foundation Case 01's QA system tested and traced problems back to. Fixing it meant two different projects, in sequence: rebuilding the measurement layer itself with better formulas and full-coverage metrics, and only then building a way to scale that foundation to any coach's priorities.

01 · Problem

One coach's opinion, translated into imperfect formulas.

The platform's evaluation logic depended on one set of metrics, translated from a single professional coach's subjective expertise. The formulas approximated what that coach cared about, but they were an imperfect way to actually measure the intended aspects of a user's motion; the numbers didn't reliably capture the technique they were supposed to represent.

  • Metrics that approximated technique instead of measuring it accurately
  • Formula-level gaps that left real aspects of a user's motion unmeasured
  • No foundation flexible enough to represent a second coach's priorities, let alone a customer's own coaching voice
  • Downstream errors that traced back to the formulas themselves, not just noisy input data

Case 01's validation pipeline traced its unreliable output directly to gaps like these. Fixing them was critical for the performance of the platform's pipelines, not just a knowledge-engineering nice-to-have.

02 · Approach

Two phases, in sequence.

Fixing an imperfect measurement layer meant solving one problem before the other was even worth attempting: rebuilding the metrics themselves, then building a way to scale them to any coach's voice.

Phase 01 · Rebuilding the Measurement Layer

Better formulas, full coverage, extended pipeline

Rewrote the metrics measurement formulas at the source, replacing the original coach-translated approximations with formulas that more accurately evaluated technique. Extended metric collection to cover the full range of measurable aspects of a sports motion, not just the subset one coach's model had used.

The rewrite reached upstream into the pipeline itself: extending LSTM model capabilities for event-detection gates and boundaries, and object-detection logic, so the platform could generate the inputs the new formulas actually needed. It also meant extending the statement of work with the data annotation and ML teams, and running extensive QA and pipeline testing evaluations before any of it reached production.

Documented all of it, mechanics, measurement systems, allowances, dashboards, user feedback, in a tutorial and guide built for internal engineering use and external customer-facing use alike.

Output 12 → 33 metrics, a 175% increase in coverage, backed by formulas rewritten for accuracy rather than convenience.
Phase 02 · SME Intake for Scale

One process, any coach's voice

With an accurate, comprehensive measurement layer in place, built a structured interview intake process: a repeatable way to translate a coach's subjective, prioritized factors in sports mechanics technique into the specific metrics that already existed and already fit the pipeline's processing capabilities.

That's the mechanism that makes the platform scalable. No new metrics to invent and no new engineering per customer; the intake process maps a coach's priorities onto a measurement library already built to represent them.

Output 7 structured intake interviews behind a white-labeled analysis engine tuned to a customer's coaching voice, delivered fast.
Phase 02 only works because Phase 01 came first — an intake process is only as good as the metrics it maps onto.
Scaling to any coach's voice was never the hard part. Measuring technique accurately enough that scaling meant anything was.
03 · Key Decisions

Six decisions that put accuracy before scale.

Decision 01

Fix the Measurement, Not Just the Politics

Rewrote the metric formulas themselves before attempting to make the system more configurable. A scalable intake process is only as good as the metrics it maps onto.

Decision 02

Extend the Pipeline, Not Just the Framework

The rewrite reached into LSTM event-detection gates and boundaries and object-detection logic, and required extending the SOW with the data annotation and ML teams, not just new evaluation rules.

Decision 03

QA the Rewrite Like a Release

Extensive QA and pipeline testing evaluations validated the new formulas before they replaced the originals in production.

Decision 04

Document for Customers, Not Just Engineers

The tutorial and guide covering mechanics, measurement systems, allowances, dashboards, and user feedback was built for internal and external use from the start.

Decision 05

Intake Maps to What Already Exists

The SME interview process translates subjective coaching priorities onto metrics already in the library and already fitting pipeline capacity, so scaling never requires bespoke engineering.

Decision 06

Design for a Customer's Voice, Not a Generic One

The payoff was speed: a white-labeled analysis engine tuned to each customer's coaching philosophy, delivered fast because the foundation underneath it didn't have to change.
